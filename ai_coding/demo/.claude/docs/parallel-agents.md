# 并行 Agent 与协作链

需要一次改很多处时，可以让多个 agent 并行干活。金币钱包是资金域，选任务要保守。

## 何时用、何时别用

| 适合并行 ✅ | 必须串行 + 人审 ❌ |
|---|---|
| 给各 handler 补输入校验、补测试 | 金币发放/消费的金额逻辑 |
| 机械重命名、统一错误映射写法 | 并发/锁相关改动 |
| 补文档注释 | 跨层重构（改依赖方向） |

判据：**机械、各单元独立、改错影响有限**才并行；**涉及资金、跨层耦合、需逐行把关**的串行人审。
并行单元之间**文件必须不相交**，否则合并冲突——按"一层/一个文件"切最稳。

## 三类扩展怎么区分（别混）

| 载体 | 位置 | 是什么 | 怎么触发 |
|------|------|--------|----------|
| **persona** | `.claude/docs/agent-*.md` | 工作流人格文档（**约定，非内置**） | plan 里指明"采用某 persona" |
| **子代理 agent** | `.claude/agents/*.md` | 内置特性，独立 system prompt | 主代理按需委派 |
| **skill / 命令** | `.claude/skills/` | 可复用技能 | 你手动敲 `/xxx` |

## 协作链

```
developer（N worker，各自分支，持续小步提交）
      │
      ▼
code-reviewer  ── merger 合并前评审闸门
      │            REJECT/NEEDS_WORK → 退回 developer；APPROVE → 才合
      ▼
merger（评审 → git merge → lint+vet+test → 循环）
      └─ 资金域（发放/消费）：闸门 + 人审 才合
```

## 三个要点（这套能跑顺的关键）

1. **评审要串进链路，别悬空**：光写 reviewer persona 没用，必须在 merger 的"合并前"显式
   插一步调它（`/code-review-go --diff`），否则 review 永远不会发生。
2. **规则要强制前置**：每个 persona 都以「先读规则」为显式第一步，比开头一句软引用可靠。
3. **资金域叠人审**：评审闸门是自动兜底，不替代人审；金币发放/消费闸门过了也要人确认。

## 红线
- 并行单元文件不相交，改完各自 `make vet && make test` 自验证
- 资金域改动串行 + 人审，不并行、不自动合
